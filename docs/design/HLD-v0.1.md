# 《山徑殘響- Trail Echoes》 High-Level Design v0.3

## 第一章：《白盲—消失的滑雪場》

---

# 1. 文件目的

本文件定義《山徑殘響》第一個可遊玩的 Vertical Slice。

第一章以 **合歡東峰**為舞台，建立一個 20 至 30 分鐘內可以完成的第一人稱探索體驗，驗證以下假設：

1. 玩家是否會因為台灣高山環境本身而產生探索動機。
2. 沒有戰鬥與 Jump Scare 的情況下，環境音效、霧氣與歷史遺跡是否足以建立沉浸感。
3. 「登頂徽章」與圖鑑收集是否能讓玩家期待探索下一座山。
4. 真實地景、歷史線索與少量神秘敘事是否能形成可持續擴充的遊戲框架。
5. 玩家是否願意透過操作無線電、相機與離線地圖，主動理解環境，而不是被動觀看劇情動畫。

本文件不是完整遊戲企劃。第一版不追求完整百岳模擬，也不追求 AAA 級山岳建模。

---

# 2. 專案概述

## 2.1 專案名稱

**《山徑殘響》**
英文暫名：**Trail Echoes**

## 2.2 第一章名稱

**第一章：《白盲——消失的滑雪場》**
英文：**Chapter One: Whiteout — The Vanished Ski Field**

## 2.3 遊戲定位

一款以台灣百岳為舞台的 **第一人稱山岳探索 RPG**。

玩家將透過步行、觀察、攝影、調查與登頂，逐步理解每座山的地景、歷史、生態與傳說。

## 2.4 一句話描述

> 玩家親自走進台灣百岳，在完成登頂的同時，發現散落於山徑上的歷史痕跡與無法辨識來源的訊號。

## 2.5 核心設計比例

| 元素      |  比例 | 說明              |
| ------- | --: | --------------- |
| 真實登山感   | 70% | 地形、天候、腳步、視野與孤獨感 |
| 歷史與環境敘事 | 20% | 遺跡、照片、紀錄、圖鑑     |
| 神秘感     | 10% | 無線電雜訊、視覺錯覺、未知訊號 |

# 3. 設計原則

## 3.1 山是主角

玩家不是來山上打怪，也不是來被鬼追逐。

遊戲的核心是：

* 走進山
* 理解山
* 尊重山
* 留下登頂紀錄

## 3.2 神秘感不等於恐怖

神秘氛圍主要來自：

* 起霧
* 視野縮短
* 遠處難以辨識的剪影
* 斷續的無線電雜訊
* 過去與現在的痕跡重疊
* 風吹箭竹形成的短暫錯覺
* 頭燈照射下產生的影子變形

第一章不使用：

* Jump Scare
* 惡靈追逐
* 血腥畫面
* 明確出現的超自然怪物
* 山難受害者獵奇化
* 將百岳塑造成危險禁地

## 3.3 神秘事件保持多重解讀

未知訊號不會在第一章被定義為：

* 外星訊號
* 靈異訊號
* 軍事訊號
* 山神傳訊

玩家只能確認：

* 訊號確實存在
* 訊號具有規律
* 設備無法識別來源
* 某些環境條件可能影響訊號強度

其餘解釋保留給後續章節。

## 3.4 歷史敘事必須可追溯

正式版本引用歷史事件、遺址、地方文化或原住民族故事前，必須：

1. 查核可靠史料。
2. 區分史實、地方傳聞與創作改編。
3. 避免直接消費真實山難受害者。
4. 涉及原住民族文化時，優先採用公開授權資料，並在正式製作階段尋求適當顧問協助。
5. 避免將族群歌曲、祭儀或神話僅作為恐怖氛圍素材。

# 4. MVP 範圍

## 4.1 第一章地點

**合歡東峰步道**

場景由登山口附近開始，沿步道向上，經過滑雪活動相關遺址與箭竹草坡，最後抵達合歡東峰山頂。

實際場景配置在開發前需要透過：

* 現地踏查
* GPX 軌跡
* 公開 DEM
* 歷史照片
* 遺址位置查核

進一步確認。

## 4.2 遊戲時間

單次遊玩時間：

**20 至 30 分鐘**

## 4.3 MVP 必須包含

* 第一人稱移動
* 一條可完成的登山路線
* 一個歷史支線
* 一次白牆天候事件
* 一個登頂成就
* 一段可操作的無線電訊號互動
* 一次輕微的環境錯覺演出
* 一次保溫瓶互動
* 基本圖鑑
* 基本存檔

## 4.4 MVP 明確不包含

* 戰鬥
* 敵人 AI
* 開放世界
* 多人連線
* 飢餓、口渴與體溫數值模擬
* 完整重量計算
* 上河速度輸入
* 裝備打造
* 角色升級樹
* 隨機生成地圖
* LLM 動態生成對話
* 100 座百岳完整內容
* 複雜訊號分析模擬器
* 明確的超自然結論

# 5. 遊戲形式與風格

## 5.1 遊戲形式

**3D 第一人稱探索遊戲**

玩法類型：

* Walking Simulator
* 環境敘事
* 輕度互動
* 輕度 RPG 收集
* 微型解謎
* 無 UI 體感回饋

參考方向：

* 《Firewatch》：孤獨感、環境探索、無線電懸疑感
* 《還願》：場景敘事、物件細節、聲音設計
* 《The Long Dark》：自然環境壓迫感
* 台灣山岳紀錄片：地景、天候與聲音質地

## 5.2 美術風格

**Semi-Realistic Stylized 3D**

不是追求照片級寫實，而是：

* 保留合歡山地貌辨識度
* 突出箭竹、碎石路與高山草坡
* 加強雲霧、風與光影
* 使用略帶電影感的低飽和色調
* 在晴朗與白牆狀態間形成鮮明對比
* 利用剪影而不是高精度模型製造心理錯覺

## 5.3 敘事風格

敘事不依賴長篇文字。

玩家透過以下元素拼湊故事：

* 泛黃照片
* 遺址
* 舊告示牌
* 聲音片段
* 無線電雜訊
* 地景變化
* 圖鑑文字
* 訊號操作結果

# 6. 核心遊戲循環

玩家每隔數分鐘會重複以下循環：

1. 沿著山徑前進。
2. 觀察地景或發現異常物件。
3. 使用相機、手電筒、無線電或地圖進行互動。
4. 解鎖歷史圖鑑或任務線索。
5. 面對天候與視覺環境變化。
6. 透過聲音、畫面抖動與呼吸節奏理解角色狀態。
7. 抵達山頂並獲得 Summit Badge。

第一章的核心問題不是：

> 玩家能不能存活？

而是：

> 玩家會不會因為下一個地景、線索與山頂而願意繼續往前走？

# 7. 遊戲場景

## 7.1 場景分區

| 區域          | 場景功能     | 核心體驗              |
| ----------- | -------- | ----------------- |
| Zone A：起點   | 教學、建立方向感 | 晴朗、開闊、可見山徑        |
| Zone B：步道前段 | 基本移動與攝影  | 腳步、風聲、箭竹          |
| Zone C：遺址區  | 歷史支線核心   | 舊照片、遺址、物件互動       |
| Zone D：白牆區  | 氛圍轉折     | 起霧、視野下降、聲音放大、短暫錯覺 |
| Zone E：山頂   | 主線完成     | 登頂徽章、無線電調頻互動      |

## 7.2 場景製作方法

### 宏觀地形

使用：

* 公開 DEM
* QGIS
* Heightmap
* Unreal Engine Landscape

目標是建立可辨識的地形起伏，而不是 1:1 重現整座山。

### 中尺度環境

使用：

* 步道
* 箭竹草坡
* 岩石
* 路標
* 木棧道或階梯
* 遺址周邊地貌
* 遠處模糊剪影

以模組化資產組合。

### 微觀互動物件

優先投入細節的物件：

* 泛黃照片
* 舊告示牌
* 登山牌
* 無線電
* 相機
* 三角點
* 生鏽鐵件
* 歷史紀錄
* 保溫瓶

部分物件可透過現地攝影或 Photogrammetry 製作，但 MVP 階段不強制。

# 8. 主線任務

## Mission 001：登上合歡東峰

### 任務目標

從起點沿步道前進，抵達合歡東峰山頂。

### 任務流程

1. 於登山口附近開始遊戲。
2. 熟悉 WASD、滑鼠視角與互動鍵。
3. 沿山徑向上。
4. 抵達遺址區域。
5. 觸發白牆事件。
6. 在能見度下降的情況下繼續沿步道前進。
7. 遭遇一次環境錯覺。
8. 抵達合歡東峰山頂。
9. 與山頂牌互動。
10. 解鎖 `Summit Badge #001：合歡東峰`。
11. 操作無線電尋找訊號來源方向。
12. 成功鎖定訊號後，設備顯示無法辨識來源。
13. 畫面淡出，顯示第一章結束。

---

# 9. 支線任務

## Side Quest 001：白色年代

### 任務目標

調查合歡東峰附近與過往滑雪活動相關的歷史痕跡。

### 收集要素

MVP 預計放入三個可調查物件：

1. 一張泛黃照片。
2. 一處遺址或設施痕跡。
3. 一段簡短歷史紀錄。

### 完成條件

找到三項線索中的至少兩項。

### 完成獎勵

解鎖圖鑑：

`Archive Entry #001：合歡山的白色年代`

### 敘事原則

歷史圖鑑應清楚區分：

* 經查核的史實
* 合理推測
* 遊戲創作內容

## Hidden Event 001：未知訊號

### 觸發條件

玩家完成登頂互動。

### 表現形式

* 無線電突然出現雜訊。
* 訊號強度短暫升高。
* 玩家需要調整天線方向與接收頻率。
* 當玩家接近正確設定時，訊號雜訊逐漸減少。
* 鎖定後出現一段規律脈衝。
* 設備顯示：`Source: Unidentified`。

### 用途

作為後續章節共通伏筆。

# 10. 玩家操作與基本需求

## 10.1 基本操作

| 操作           | 按鍵    |
| ------------ | ----- |
| 移動           | WASD  |
| 視角           | 滑鼠    |
| 互動           | E     |
| 步行 / 衝刺      | Shift |
| 手電筒          | F     |
| 相機           | C     |
| 無線電          | R     |
| 離線 GPS 或紙本地圖 | M     |
| 保溫瓶          | H     |
| 暫停選單         | Esc   |

## 10.2 玩家基本需求

玩家需要：

* 找到正確路徑
* 注意環境提示
* 在濃霧中維持方向感
* 主動調查物件
* 辨識哪些影像只是環境錯覺
* 完成登頂
* 操作無線電完成第一次訊號鎖定

MVP 不要求玩家計算補給，也不懲罰未帶特定裝備。

# 11. 遊戲系統

## 11.1 裝備系統

### MVP 設計

採用 **固定工具列**。

玩家預設持有：

| 工具           | 功能            |
| ------------ | ------------- |
| 相機           | 拍攝遺址、記錄圖鑑     |
| 實驗無線電        | 接收訊號、執行簡化調頻互動 |
| 手電筒          | 白牆與低光場景輔助     |
| 離線 GPS 或紙本地圖 | 顯示位置與路線       |
| 保溫瓶          | 緩解寒冷演出與鏡頭顫抖   |

### 後續版本

若 MVP 驗證成功，再加入：

* 裝備格限制
* 輕量化取捨
* 雨衣
* 頭燈電池
* 水與食物
* 行動糧
* 保暖層
* 濾水器
* 不同路線的裝備需求

## 11.2 無線電互動系統

### 目標

將訊號事件從被動動畫改為簡單、可理解的操作解謎。

### MVP 操作

玩家按下 `R` 開啟裝置畫面。

介面包含：

* 訊號強度條
* 頻率調整旋鈕
* 天線方位指示
* 雜訊波形
* 鎖定提示

玩家需要：

1. 水平轉動角色方向。
2. 使用滑鼠滾輪或鍵盤微調頻率。
3. 觀察訊號強度。
4. 找到強度最高區域。
5. 鎖定訊號。

### 設計限制

* 完成時間控制在 1 至 3 分鐘。
* 不需要真實 RF 工程知識。
* 保留工程操作感，但不能成為專業儀器模擬器。
* 提供簡單模式，避免玩家卡關。

## 11.3 地圖系統

MVP 不使用永遠顯示的小地圖。

玩家需要主動拿出：

* 紙本地圖
* 離線 GPS
* 手機 GPX 畫面

地圖顯示：

* 當前位置
* 已走軌跡
* 主要路線
* 山頂方向

白牆期間：

* 畫面能見度下降
* 地圖仍可使用
* GPS 可短暫延遲
* 不可讓玩家陷入無法完成任務的狀態

## 11.4 補給系統

MVP 階段不設：

* 飢餓值
* 口渴值
* 體溫值

僅保留保溫瓶互動，作為：

* 節奏停頓
* 動畫演出
* 聲音設計
* 寒冷狀態回饋
* 未來補給系統接口

## 11.5 攝影與圖鑑系統

玩家可使用相機記錄特定物件。

成功拍攝後：

* 顯示簡短 UI 提示
* 新增圖鑑項目
* 更新支線任務進度

MVP 不需要自由攝影評分。

## 11.6 登頂與成就系統

每座百岳具有唯一識別碼。

範例：

| 欄位        | 值                   |
| --------- | ------------------- |
| Summit ID | `TW100-HEHUAN-EAST` |
| 名稱        | 合歡東峰                |
| 海拔        | 由正式資料來源填入           |
| 區域        | 合歡山群                |
| Badge ID  | `BADGE-001`         |
| 解鎖條件      | 與山頂牌互動              |

未來成就：

* 第一座百岳
* 合歡群峰收集
* 雪霸區域收集
* 中央山脈收集
* 完成 10 岳
* 完成 50 岳
* 完成百岳

# 12. 數值與狀態系統

## 12.1 血量

MVP **不設血量**。

理由：

* 第一章不包含戰鬥。
* 不希望把自然環境簡化成扣血陷阱。
* 避免偏離探索體驗。

## 12.2 體力

MVP 不顯示 Stamina Bar。

玩家連續衝刺或爬坡後：

* 移動速度略微下降
* 呼吸聲加重
* 視角產生輕微晃動
* 停止衝刺後自然恢復

需提供設定選項，允許玩家降低或關閉視角晃動，以避免暈動症。

## 12.3 時間系統

MVP 使用 **腳本式時間推進**。

| 階段  | 場景狀態           |
| --- | -------------- |
| 起點  | 上午至中午、晴朗       |
| 遺址區 | 雲量增加           |
| 白牆區 | 霧氣快速形成         |
| 山頂  | 低能見度、強風、短暫光線變化 |

MVP 不實作完整日夜循環。

## 12.4 天候與寒冷回饋

MVP 包含兩種天候狀態：

1. `Clear`
2. `Fog`

轉換由關卡事件控制。

當玩家進入白牆或山頂強風區：

* 畫面邊緣出現極輕微冷霧或霜化濾鏡
* 鏡頭產生可調整的微幅顫抖
* 呼吸聲加重
* 角色吐出白氣
* 衣物摩擦聲增加

玩家使用保溫瓶後：

* 角色停下喝熱水
* 冷霧濾鏡逐步減弱
* 顫抖短暫停止
* 呼吸節奏恢復

### 設計限制

* 不使用過重的結冰畫面。
* 不讓玩家誤以為角色已進入極端失溫。
* 保溫瓶不作為強迫使用的生存資源。
* 特效強度需提供設定選項。

## 12.5 白牆事件

### 設計目的

* 建立第一章氣氛轉折。
* 測試 Volumetric Fog。
* 讓玩家意識到路標、地圖與聲音的重要性。
* 透過環境錯覺增加注意力與心理張力。

### 基本效果

* 能見度降低
* 風聲加強
* 遠處聲音模糊
* 腳步聲更加明顯
* 無線電出現短暫雜訊
* 路線仍然可辨識

### 環境誤導效果

白牆事件中，可在少量固定位置加入 **Environmental Misdirection**：

* 風吹箭竹形成類似人影的剪影
* 登山杖或路標在頭燈下形成拉長影子
* 遠方岩石輪廓短暫像是站立的人
* 玩家轉頭後，剪影恢復成普通環境物件

### 實作限制

* 不產生實際敵人。
* 不使用 AI 追蹤。
* 不播放鬼影動畫。
* 每次錯覺控制在 1 至 2 秒。
* 第一章最多使用 1 至 2 次。
* 玩家回頭確認時，必須能找到合理的自然來源。

### 設計限制

白牆事件不應造成：

* 玩家長時間迷路
* 任務不可完成
* 過度挫折
* 百岳被描繪成超自然禁地

# 22. MVP 驗收條件

## 22.1 功能驗收

玩家可以：

* 從起點走到合歡東峰山頂
* 使用 E 與物件互動
* 找到至少兩個歷史線索
* 觸發白牆事件
* 遭遇一次合理的環境錯覺
* 使用相機
* 開啟地圖
* 使用保溫瓶
* 獲得第一個 Summit Badge
* 解鎖歷史圖鑑
* 操作無線電完成訊號鎖定
* 觸發未知訊號伏筆
* 儲存並讀取進度

## 22.2 體驗驗收

邀請少量測試者遊玩後，蒐集：

1. 玩家是否能在沒有口頭提示下完成登頂。
2. 玩家是否願意主動查看歷史物件。
3. 白牆是否有氣氛，但不至於令人煩躁。
4. 環境錯覺是否讓玩家提高警覺，而不是覺得遊戲突然變成廉價恐怖片。
5. 無線電操作是否具有工程感，但不會卡關。
6. 保溫瓶互動是否增加登山共鳴，而不是變成無意義動畫。
7. 玩家是否理解這是一款山岳探索遊戲，而不是恐怖遊戲。
8. 玩家是否期待下一座山。

# 25. 第一個開發決策

第一個技術里程碑不是做 UI，也不是掃描道具。

應先完成：

> 使用 Unreal Engine 5 匯入合歡東峰區域 Heightmap，建立一條可從起點走到山頂的 Greybox 路線。

只有當玩家可以實際走完整段山徑，才能判斷：

* 地圖比例是否合理
* 遊玩時間是否過長
* 第一人稱爬坡是否有趣
* 哪些區域適合放入遺址
* 白牆事件應該在哪裡觸發
* 無線電解謎放在山頂是否具有節奏上的效果
